# План движка Hashpix Automation

Первый результат на физическом телефоне: открыть панель, подключить Android по USB, разрешить отладку, увидеть экран и управлять им из браузера. Затем тот же контур связывается с очередью сценариев, хранилищем материалов и публикациями. Next.js остаётся интерфейсом и локальным HTTP API.

## Границы компонентов

| Компонент | Ответственность |
| --- | --- |
| Next.js | Панель, настройка хоста, HTTP API, авторизация, чтение состояния и отправка команд |
| Локальный исполнитель | Долгоживущие сессии устройств, поток событий, фоновые работы, таймеры и восстановление |
| Драйвер Android | Обнаружение через ADB, кадры и базовые жесты, scrcpy для видеопотока, UiAutomator2 для селекторов |
| Драйвер iOS | Доверие и доступность, WDA и XCTest, подготовка подписи и проверка реальных возможностей по хостам |
| Хранилище | SQLite с миграциями, отдельные каталоги для медиа, скриншотов и журналов, секреты в системном хранилище |
| Адаптеры интеграций | Narezai, OAuth, HTTP, отправка публикаций и сверка внешних статусов |

Начальный Android-адаптер работает внутри Node.js-процесса Next.js, чтобы протянуть сквозной путь без отдельной установки службы. Контракт драйвера должен позволить вынести исполнение в отдельный процесс при появлении долговременных сессий или потока. Версии ADB, scrcpy и Appium закрепляются на первом проверенном стенде. На macOS и Windows запуск использует собственный локальный ADB. Доступ по LAN вводится отдельным этапом.

## Этапы и приёмка

### 1. Android по USB

- Найти Platform Tools и показать состояние ADB, серийный идентификатор и модель. Различать отсутствие устройств, запрос разрешения, обрыв связи и недоступный драйвер.
- Получить PNG через ADB, показать обновляемые кадры и время последнего удачного кадра. Пауза опроса скрытой вкладки, ограничение параллелизма, объединение конкурирующих запросов к одному телефону.
- Отобразить выбранный экран в его реальном соотношении сторон. Координаты тапа и свайпа переводить из относительных в пиксели текущего кадра. При смене размеров просить повторить жест на свежем кадре. Добавить команды «Назад» и «Домой». Кириллица, мультитач и ввод специальных символов требуют отдельной проверки инъекции ввода.
- Приёмка на Redmi: разрешить отладку, увидеть кадр, открыть приложение тапом, прокрутить свайпом, повернуть устройство, вынуть USB и восстановить управление после переподключения без перезагрузки страницы.

### 2. Поток и несколько устройств

- Поставить версионированный scrcpy-адаптер на Android. Получать H.264, передавать браузеру через выбранный медиатранспорт, измерять задержку до решения о режиме передачи. Снимки ADB служат резервным режимом.
- Развести качество активного просмотра и фоновых плиток, ограничить суммарный битрейт и число активных декодеров. При нескольких вкладках переиспользовать сессию источника. Экран и доступность команд отслеживаются отдельно.
- Завести диспетчер сессий, правила владения телефоном и очереди команд на устройство. Просмотр не требует захвата. Ручное управление и workflow получают взаимоисключающий доступ к действиям.
- Приёмка: два разных телефона отображаются одновременно. Отключение одного не затрагивает второго. Проверить отдельную вкладку стены, повороты, переключение качества и нагрузку в нескольких браузерах. Число поддерживаемых телефонов публикуется после замеров, а не по расчёту.

### 3. Исполнитель сценариев и расписания

- Перенести графы и запуски в SQLite. Сохранять неизменяемую версию графа и входные данные на каждый запуск. Проверять типы портов, достижимость, ветвления, ограниченные циклы и список возможностей до выполнения.
- Сделать зарегистрированные обработчики для Start, Tap, Swipe, Home, Back, Screenshot, Delay, If, Log и Stop. Затем добавить Appium, поиск/ожидание элемента, параметры приложения, типизированные переменные, вложенные графы и разрешённые интеграции.
- Долгие ожидания хранятся в базе. Отмена пробрасывается до отдельной команды. После обрыва или тайм-аута различать безопасный повтор и неизвестный внешний результат. Ошибки содержат снимок, параметры без секретов и ссылку на ноду.
- Добавить очередь и триггеры по расписанию, поступлению файла и подключению. Указание часового пояса, политика пропуска при сне хоста, управляемый параллелизм по устройствам.
- Приёмка: запуск переживает закрытие вкладки, а безопасное ожидающее задание восстанавливается после рестарта сервера. Из интерфейса можно остановить работу, найти проблемный шаг и выполнить безопасный повтор.

### 4. Контент и публикации

- Реальный импорт с хостовой папки, из загрузки и из Narezai после согласования контракта. Проверка формата и длительности, версии исходников, отдельные варианты под площадки.
- Локальные черновики, согласование, очередь, ручное завершение и проверенный провайдер публикации. Публикация хранит аккаунт, версию ролика, статус, часовой пояс, идентификатор операции и подтверждённую ссылку.
- Перед повтором отправки сверять внешний статус. Успешная загрузка и публикация отражаются как разные события. Ноды API имеют ограничение сетевых адресов и авторизованные подключения. Секреты маскируются в результатах.
- Приёмка: реальный ролик проходит импорт, согласование, постановку в очередь и подтверждение по одному каналу. Другой канал может завершаться оператором.

### 5. iPhone, хосты и поставка

- Ранний отдельный стенд iPhone параллельно первому Redmi. На macOS проверить Xcode, доверие устройству и подписанный WDA. Windows проверять на конкретной версии iOS, с RemoteXPC и подготовленным WDA. Возможности автоматически объявляются по результатам проверок.
- Локальный запуск на Windows/macOS и установка зависимостей по инструкции. Затем авторизация LAN, журнал доступа, диагностика и, при необходимости, подключение второго хоста через агент.
- Приёмка: повторное подключение и восстановление после перезагрузки, журнал диагностики без секретов, отсутствие состояния «готово» при ошибке драйвера или подписи.

## Контракт Android и серверных запусков

- `GET /api/engine/android` — доступность ADB и текущее состояние устройств.
- `GET /api/engine/android/:serial/frame` — PNG с заголовком времени кадра.
- `GET /api/engine/android/:serial/video` — общий H.264-поток scrcpy 3.3.4 с маркировкой ключевых кадров. Один кодировщик на телефон, клиенты перезапускают просмотр после обрыва.
- `GET /api/engine/runs` — журнал сервера. `POST` принимает граф и устройство, проверяет все ноды и маршрут, захватывает право на команды телефона. `DELETE /api/engine/runs/:id` отменяет запуск.
- `POST /api/engine/android/:serial/input` — строго типизированные тап, свайп и системные кнопки.
- Команды доступны с loopback-интерфейса. Веб-запросы с чужого origin отклоняются. Устройства требуют обычного разрешения USB-отладки в Android.
- UI показывает реальные устройства в основном режиме и хранит примеры под отдельным переключателем. Редактор передаёт снимок графа для живого исполнения. Прогресс и результаты читаются с сервера, редактируемые графы пока сохраняются в браузере. Материалы и публикации переходят на серверный контракт по этапам выше.
