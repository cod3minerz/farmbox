# Дизайн-система Hashpix Automation

Рабочая версия для проектирования. Hashpix Automation — тёмная настольная веб-панель для наблюдения за телефонами, управления сценариями и выпуска контента. Её визуальный язык строится на общей сетке, тонких стыках панелей, моноширинном интерфейсном тексте и коротких светлых уголках вокруг выбранного объекта.

## Референсы и приоритет

| Источник | Что переносим в систему |
| --- | --- |
| № 3, APEX. Главный референс оболочки | Плоские графитовые поверхности, прямые углы, спокойная иерархия, единая высота строк. У `New task` берём приём серого света внутри строки и четырёх отдельных Г-образных меток. В Hashpix этот приём обозначает текущий раздел. |
| № 1–2, HockeyStack | Плотность навигации, выравнивание иконок, отступы между группами. Для правой панели — ритм строк «параметр / значение» и маленькие цветные значки, когда цвет несёт смысл. |
| № 4, список задач | Моноширинный ритм, тонкие линии и светлый квадрат на важном пересечении. Активная вкладка читается по короткой светлой черте. |
| № 5–7, терминальные композиции | Моноширинные данные, штрихи шкал, компактные статусы. Сегменты применяются там, где есть измеряемый прогресс, например при загрузке ролика. |
| № 8, меню профиля | Чёткое разделение групп, контраст главного действия и мягкий перепад между нейтральными поверхностями. Форму элементов задаёт референс № 3. |
| № 9–10, Attio | Линии панелей и внутренних колонок совпадают по осям. Редкие метки пересечения, тонкие полосы и схемы уместны в диагностике и метриках. |
| Конструктор, референсы 1–2 | Просторный холст, малоконтрастная сетка, ясные порты и подписи. Режим выполнения получает отдельную панель и выделяет наблюдаемый маршрут. |
| Конструктор, референсы 3–4 | Подписанные переходы, читаемые ветвления и строки «параметр / значение» внутри нод. |
| Конструктор, референсы 5–6 | Компактная сводка внутри ноды, локальный цвет действия и каталог с поиском, группами и избранным. |

Приоритет при конфликте — APEX для геометрии оболочки, референсы конструктора для композиции и поведения графа, HockeyStack для плотности и иконок, терминальные примеры и Attio для графических деталей.

## Сетка и геометрия

Базовые размеры ниже приведены для 16 px в корне. Интерфейс использует корневой масштаб 110% и единицы rem для текста, отступов и размеров элементов.

| Элемент | Стартовое значение |
| --- | --- |
| Шкала отступов | `4 / 8 / 12 / 16 / 24 / 32 / 48 px`. `4` внутри компактной группы, `8` между иконкой и подписью, `12–16` внутри компонентов, `24–32` между секциями. |
| Оболочка | Левый сайдбар `208 px`, свёрнутый `52 px`. Центральная область занимает оставшуюся ширину. Инспектор по умолчанию `320 px`, в конструкторе `360 px`. На широком экране граница перетаскивается, ширина сохраняется от `248 px` до `560 px` с ограничением по ширине окна. Кнопка инспектора остаётся справа в верхней строке. |
| Верхняя строка и края | Высота `48 px` по общей оси. Боковые отступы рабочей области `24 px`, внутри сайдбаров `16 px`. Один разделитель `1 px` на стык поверхностей. |
| Элементы | Строка навигации `36 px`, интервал между соседними строками `4 px`. Строка таблицы `36 px`, базовое поле или кнопка `32–36 px`. Для сенсорного ввода область нажатия увеличивается. |
| Радиусы | `0 px` для панелей, строк навигации, нод и плиток. `2 px` для полей, кнопок и меню. Круглая геометрия у портов и точек состояния. |
| Узкий экран | Ниже `1280 px` начать со свёрнутой навигации. При ширине ниже `1100 px` инспектор открывается поверх рабочей области. Полноэкранные стена и холст сохраняют возможность вернуться к объекту. |

В состоянии выбора четыре уголка длиной `6 px` и толщиной `1 px` находятся на границе выбранного объекта. Для стыков сетки предусмотрена отдельная квадратная метка `2 × 2 px` на реальном пересечении основных осей, по одной на стык. Эти два сигнала различаются по форме и назначению.

## Цвет и состояния

Тема только тёмная. Значения ниже — предложения для первого макета. Имена токенов описывают назначение. Например, фон выбранной строки `nav-current-bg` ссылается на семантическую поверхность `surface-selected`, а она — на примитив графитовой палитры.

| Роль | Значение | Применение |
| --- | --- | --- |
| `surface-canvas` | `#0D0D0E` | Рабочий холст, стена, фон просмотра |
| `surface-panel` | `#131314` | Навигация, инспектор, панели инструментов |
| `surface-raised` | `#19191B` | Ноды и всплывающие панели |
| `surface-selected` | `#1C1C1D` | Выбранный объект или раздел |
| `line-subtle` / `line-control` | `#262628` / `#66666C` | Тихий стык и различимая граница там, где без неё теряется форма поля |
| `text-primary` / `text-secondary` / `text-muted` | `#EDEDEC` / `#ACACB0` / `#8C8C92` | Основной текст, вторичная информация и читаемые метаданные |
| `focus` | `#C9C9CD` | Нейтральный клавиатурный контур `1 px` с отступом `2 px`. У текстовых полей заменяет их внутреннюю границу |
| `success` / `warning` / `error` / `info` | `#6ED7A0` / `#EDC47A` / `#F28D8D` / `#85ADFF` | Готовность, предупреждение, ошибка и выполнение. Состояние сопровождается текстом или узнаваемым знаком. |

**Навигация:** в покое фон совпадает с сайдбаром. При наведении появляется лёгкое повышение яркости. Текущий раздел получает `aria-current`, светлую подпись, четыре метки и мягкий серый свет внутри строки. Начальное значение для подбора — внутренний верхний блик `1 px` с белым на `8%` и рассеянный внутренний ореол до `12 px` на `4%`. Клавиатурный фокус виден поверх любого состояния. Одиночный выбор телефона и ноды использует ту же форму. Множественный выбор телефонов обозначается чекбоксами.

**Действия:** основная кнопка — светлая с тёмным текстом. Вторичное действие — графитовое или текстовое. Красный выделяет ошибку или действие с серьёзным последствием. Палитра категорий конструктора занимает область иконки. Статус выполнения располагается отдельной меткой с подписью. Столбцы действий в инспекторе занимают всю доступную ширину и имеют одинаковые боковые отступы. Списки выбора и календарь используют графитовые поверхности, чёткие края и нейтральный фокус.

## Типографика и иконки

**Geist Mono** — рабочий шрифт меню, кнопок, заголовков нод, форм и чисел. **Unbounded Medium** — широкий заголовок корневых разделов, например «Устройства» или «Автоматизации». В редакторе и деталях объектов заголовки остаются компактными моноширинными. Оба семейства доступны с кириллицей. Шрифты в приложении следует хранить локально для работы без интернета. [Geist Mono](https://raw.githubusercontent.com/google/fonts/main/ofl/geistmono/METADATA.pb) · [Unbounded](https://raw.githubusercontent.com/google/fonts/main/ofl/unbounded/METADATA.pb)

| Роль | Размер / высота строки | Начертание |
| --- | --- | --- |
| Заголовок корневого раздела | `24 / 32 px` | Unbounded `500` |
| Заголовок панели | `16 / 24 px` | Geist Mono `600` |
| Навигация, формы, строки, ноды | `13 / 20 px` | Geist Mono `400`, акцент `500–600` |
| Логи, значения и вторичные подписи | `12 / 18 px` | Geist Mono `400–500` |
| Длинное пояснение или ошибка | `14 / 22 px` | Geist Mono `400`, переносы |

Для навигации и действий используем Iconsax. Обычное состояние — TwoTone, выбранное, раскрытое или нажатое — Bulk. Для обновления локальных вариантов есть команда `npm run icons:sync`. [Iconsax](https://iconsax.io/). Базовый размер `16 px`, промежуток до подписи `8 px`. Для категорий нод и интеграций — знак `16 px` в квадрате `24 px`. Цвет применяется к категории, интеграции или статусу. В главном меню яркость иконки подчиняется яркости подписи. Верхний регистр допустим у коротких технических меток.

## Экраны, которые проверяют систему

- **Стена устройств.** Главный объект — крупное изображение экрана. Телефоны стоят на общем фоне без внешних карточек. Название, идентификатор, ОС и статус идут непосредственно под изображением по его левому краю. Уголки обозначают телефон, открытый в инспекторе. Чекбокс множественного выбора находится поверх экрана. Колонки резиновые, горизонтальный зазор `12 px`. В табличном режиме мини-превью стоит в одной ячейке с названием устройства. Режим отдельной вкладки использует экран под стену и сохраняет фильтры.
- **Конструктор.** Шаг привязки к сетке `16 px`, видимая точка сетки слабее линий связей. Нода шириной `208 px` включает знак, название, подписанные значения параметров и многострочный предпросмотр текста. Управляющий маршрут идёт слева направо. Передача данных отличается формой порта и подписью, а цвет служит вторичным признаком. Ветки подписаны рядом с выходами. При исполнении выделяются текущий шаг и пройденные связи. Каталог нод открывается по «Добавить ноду», значения редактируются в инспекторе, журнал раскрывается снизу.
- **Публикации и запуски.** Табличные списки с тонкими горизонтальными разделителями, выровненными датами и числами. История запусков отделена от хронологии выбранного запуска. У хронологии собственный заголовок с именем и идентификатором сценария, а шаги читаются по вертикальной оси. При выборе публикации, запуска или шага справа открываются параметры, действия и диагностика.

## Порядок проектирования

1. Собрать срез оболочки и комплект ключевых состояний. Навигация в покое, при наведении, в текущем разделе и с клавиатурным фокусом. Поле, основная кнопка, меню, разделитель, цветная иконка статуса.
2. Применить срез к стене на одном телефоне и к плотной сетке на двенадцати. Проверить выбор, потерю связи, занятость сценария и работу со свёрнутым инспектором.
3. Проверить редактор на простом графе и на разветвлённом сценарии. В обоих случаях найти точку входа, текущий шаг, ветку ошибки и настройки ноды.
4. Перенести систему на список публикаций и историю запусков. Проверить кириллицу, длинные имена, даты, моноширинные числа и фокус на `1024`, `1280`, `1440` и `1920 px`.

Цвета, ширины и пороги — стартовые значения. При визуальной проверке обязательны тёмная тема, приоритет геометрии третьего референса, чёткая иерархия и один набор правил для всех экранов.
